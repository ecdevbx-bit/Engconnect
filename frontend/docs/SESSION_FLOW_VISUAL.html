1 User Starts Session & Gets Level from Database

When an authenticated user clicks "Play Jumble Words", the frontend sends their idToken to the backend. The backend queries the ecUsers DynamoDB table to find the user's current level.

2 Determine Difficulty Weights Based on Level

The backend has a lookup table called DIFFICULTY_WEIGHTS that maps level ranges to difficulty percentages. Based on the user's level, we get the weights for easy, medium, and hard sentences.

Level Range Mapping:
• Levels 1-2 → 100% easy, 0% medium, 0% hard
• Levels 3-5 → 50% easy, 40% medium, 10% hard
• Levels 6-7 → 30% easy, 40% medium, 30% hard
• Levels 8-10 → 10% easy, 40% medium, 50% hard

3 Generate Random Difficulty Flow (6 Sentences)

The backend loops 6 times (SESSION_SIZE = 6). For each slot, it generates a random number between 0-100 and compares it against the weights to determine if that sentence should be easy, medium, or hard.

Algorithm:
roll = Math.random() * 100
if (roll < 50) → EASY
if (roll < 50 + 40) → MEDIUM
if (roll < 50 + 40 + 10) → HARD

4 Get Cursor Positions from Activity History

To ensure users don't see the same sentence twice, the backend queries the ecActivityHistory table to get how many sentences of each difficulty have been shown to this user in total across all previous sessions.

Database Query:
Table: ecActivityHistory
Query: Latest record for this user

Cursor Positions Retrieved:
• easyTotal: 15 (15 easy sentences already shown)
• mediumTotal: 8 (8 medium sentences already shown)
• hardTotal: 2 (2 hard sentences already shown)

5 Fetch Sentences Sequentially for Each Slot

For each difficulty in the flow, calculate the next sequential sentence ID using the formula: nextId = (cursorPosition + offset) % maxCount + 1. Then fetch that sentence from the ecContentBank table.

Content Bank Sizes:
• Easy sentences: 99 total
• Medium sentences: 60 total
• Hard sentences: 30 total

Note: The modulo (%) operation ensures we wrap around to the beginning when we reach the max, so users eventually cycle through all sentences.

5 EASY (15 + 2) % 99 + 1 19 "Dogs are very loyal animals"
6 HARD (2 + 0) % 30 + 1 3 "Implementing scalable distributed systems"
6 Return Response to Frontend

The backend sends both the flow array and the sentences array to the frontend. The frontend then uses this data to render the game session.

API Response: POST /game/jumble-words/start

✓ Complete Flow Summary

1. Get user's level from ecUsers
2. Look up weights based on level range
3. Generate 6 random difficulties using weighted distribution
4. Get cursor positions from ecActivityHistory
5. For each difficulty, calculate sequential ID and fetch from ecContentBank
6. Return flow array and sentences array to frontend
7. Frontend renders the game with these sentences

Why this design?
✓ User sees content matched to their skill level
✓ No repeated sentences across sessions
✓ Difficulty distribution adapts as user progresses
✓ Scalable: wrapping ensures infinite content rotation
