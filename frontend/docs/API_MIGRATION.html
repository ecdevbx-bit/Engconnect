Proposed Table Schema

Replaces DynamoDB single-table design with normalized MariaDB tables.

TABLE: users
id BIGINT PK firebase_uid VARCHAR(128) UNIQUE NOT NULL email VARCHAR(255) UNIQUE NOT NULL name VARCHAR(255) location VARCHAR(255) hobbies TEXT goals TEXT current_status ENUM('school','college','working') native_lang VARCHAR(100) english_reason TEXT phone VARCHAR(15) total_xp INT DEFAULT 0 current_level TINYINT DEFAULT 1 role ENUM('STUDENT','ADMIN') DEFAULT 'STUDENT' is_email_verified BOOLEAN DEFAULT FALSE created_at DATETIME DEFAULT NOW() updated_at DATETIME DEFAULT NOW() ON UPDATE NOW()
TABLE: activities
id BIGINT PK AUTO_INCREMENT user_id BIGINT FK → users.id activity_type ENUM('jumble-words','pronoun-coach','ai-partner') xp_earned INT NOT NULL easy_count TINYINT DEFAULT 0 medium_count TINYINT DEFAULT 0 hard_count TINYINT DEFAULT 0 completed_count TINYINT DEFAULT 0 total_count TINYINT DEFAULT 0 activity_data JSON created_at DATETIME DEFAULT NOW()
TABLE: sentences
id INT PK AUTO_INCREMENT text TEXT NOT NULL difficulty ENUM('easy','medium','hard') NOT NULL type ENUM('jumble','pronunciation') DEFAULT 'jumble' is_active BOOLEAN DEFAULT TRUE
TABLE: user_sentence_cursors (replaces DynamoDB sequential cursor)
id BIGINT PK AUTO_INCREMENT user_id BIGINT FK → users.id sentence_id INT FK → sentences.id played_at DATETIME DEFAULT NOW() UNIQUE KEY (user_id, sentence_id)

Auth — Sync & Register

Called automatically after Firebase login via syncWithBackend() in src/lib/auth.ts.

src/lib/auth.ts → syncWithBackend()
Endpoint
POST /api/auth/sync
-- On first login: create user row from Firebase JWT claims INSERT INTO users (firebase_uid, email, name, is_email_verified, role) VALUES (:firebaseUid, :email, :name, :emailVerified, 'STUDENT') ON DUPLICATE KEY UPDATE name = COALESCE(name, VALUES(name)), is_email_verified = :emailVerified; -- Same-email relink: user deleted Firebase account and re-registered UPDATE users SET firebase_uid = :newFirebaseUid, is_email_verified = :emailVerified WHERE email = :email AND firebase_uid != :newFirebaseUid;
⚠️ The FirebaseTokenFilter already handles this. The Spring Boot UserService.getOrCreateUser() method contains the relink logic — no additional migration needed for auth itself.

Activity History

Paginated list of completed game sessions. Replaces DynamoDB scan with LIMIT/OFFSET.

src/app/app/activity/page.tsx
src/components/app/AppNavbar.tsx (preview)
List activities (paginated)
GET /api/user/activity?limit=10&lastKey=<offset>
-- Page 1 (no lastKey) SELECT a.id, a.activity_type AS activityType, a.xp_earned AS xpEarned, a.easy_count AS easyCount, a.medium_count AS mediumCount, a.hard_count AS hardCount, a.completed_count AS completedCount, a.total_count AS totalCount, a.activity_data AS activityData, a.created_at AS timestamp FROM activities a JOIN users u ON u.id = a.user_id WHERE u.firebase_uid = :firebaseUid ORDER BY a.created_at DESC LIMIT :limit OFFSET :offset; -- Response also includes nextKey = offset + limit (or null if fewer rows returned than limit)
💡 DynamoDB used LastEvaluatedKey for pagination. Replace with integer offset. The frontend sends lastKey as a string — parse it as an integer on the backend.

Game: Jumble Words

Two-step flow: start session → play → complete session. Replaces DynamoDB sequential cursor with user_sentence_cursors.

src/components/game/AuthedJumbleWordsPlayground.tsx
src/app/app/game/jumble-words/page.tsx
Start session — fetch sentences
POST /api/game/jumble-words/start
-- Step 1: Determine user level to build session flow SELECT current_level FROM users WHERE firebase_uid = :firebaseUid; -- Step 2: Pick 6 sentences not yet seen by this user (respects sequential cursor) SELECT s.id, s.text, s.difficulty FROM sentences s LEFT JOIN user_sentence_cursors c ON c.sentence_id = s.id AND c.user_id = :userId WHERE s.type = 'jumble' AND s.is_active = TRUE AND c.id IS NULL -- not yet played AND s.difficulty IN (:d1, :d2, ...) -- from server-generated flow ORDER BY RAND() -- or deterministic ordering LIMIT 6; -- If fewer than 6 unseen sentences remain, reset cursor for this user: DELETE FROM user_sentence_cursors WHERE user_id = :userId;
Complete session — save results + award XP
POST /api/game/jumble-words/complete
-- Step 1: Record which sentences were played (advance cursor) INSERT IGNORE INTO user_sentence_cursors (user_id, sentence_id, played_at) VALUES (:userId, :sentenceId1, NOW()), (:userId, :sentenceId2, NOW()), ...; -- Step 2: Credit XP and recalculate level UPDATE users SET total_xp = total_xp + :totalXpEarned, current_level = calculateLevel(total_xp + :totalXpEarned), updated_at = NOW() WHERE firebase_uid = :firebaseUid; -- Step 3: Write activity record INSERT INTO activities (user_id, activity_type, xp_earned, easy_count, medium_count, hard_count, completed_count, total_count, activity_data) VALUES (:userId, 'jumble-words', :totalXpEarned, :easyCount, :mediumCount, :hardCount, :correctCount, 6, :resultsJson); -- Step 4: Return updated totals to frontend SELECT total_xp AS newTotalXp, current_level AS newLevel FROM users WHERE firebase_uid = :firebaseUid;
💡 DynamoDB used a cursor attribute on the user item that stored the last-seen sentence ID. SQL equivalent: the user_sentence_cursors join table. A sentence is "seen" once its row exists in that table for that user. Reset = DELETE FROM user_sentence_cursors WHERE user_id = ?.

Game: Pronunciation Coach

3-sentence session. Audio uploaded as multipart form; pipeline returns word-level analysis.

src/app/app/game/pronoun-coach/page.tsx
Start session
POST /api/game/pronoun-coach/start
SELECT s.id, s.text, s.difficulty FROM sentences s LEFT JOIN user_sentence_cursors c ON c.sentence_id = s.id AND c.user_id = :userId WHERE s.type = 'pronunciation' AND s.difficulty = :difficulty AND c.id IS NULL ORDER BY RAND() LIMIT 3;
Submit audio + complete session
POST /api/game/pronoun-coach/complete
-- XP formula: base(difficulty) × accuracy_ratio -- easy=20, medium=30, hard=40 × (correct_words / total_words) UPDATE users SET total_xp = total_xp + :totalXpEarned, current_level = calculateLevel(total_xp + :totalXpEarned), updated_at = NOW() WHERE firebase_uid = :firebaseUid; INSERT INTO activities (user_id, activity_type, xp_earned, total_count, activity_data) VALUES (:userId, 'pronoun-coach', :totalXpEarned, 3, :pronunciationResultsJson);

Implementation Notes

🔑 Auth token: Every protected endpoint receives a Firebase ID JWT in Authorization: Bearer <token>. The existing FirebaseTokenFilter verifies it and sets the firebase_uid in the security context. Use that UID to look up users.id for all queries.
📐 Level calculation: Frontend uses LEVEL_THRESHOLDS = [0, 0, 100, 250, 500, 850, 1300, 1900, 2700, 3700, 5000] (index = level). Backend should implement the same thresholds in a helper — return the level whose threshold is ≤ total_xp, checking from highest to lowest.
🚫 Public routes: /game/jumble-words and /game/pronoun-coach are unauthenticated — they use local sentence data with no backend calls. Only /app/game/* routes call the backend.
📦 Response shape frontend expects from /api/user/me: { user: { sub, name, email, location, hobbies, goals, phone, currentStatus, englishReason, nativeLang, totalXp, currentLevel, createdAt } }
📦 Response shape frontend expects from /api/game/jumble-words/complete: { newTotalXp: number, newLevel: number }
📦 Response shape frontend expects from /api/user/activity: { activities: ActivityRecord[], nextKey: string | null } where nextKey is a string-encoded integer offset (or null if no more pages).
